================================================================================
                    AGRITRADE SYSTEM SETUP GUIDE
================================================================================

This guide will help you set up the complete AgriTrade system from scratch.
Follow the steps in order to ensure everything works correctly.

The backend uses NestJS (TypeScript) with PostgreSQL database.
The mobile app uses React Native with Expo.

================================================================================
                            PREREQUISITES
================================================================================

Before starting, make sure you have installed:

1. Node.js (v18 or higher recommended, minimum v16)
   - Download from: https://nodejs.org/
   - Verify installation: node --version
   - Recommended: Use LTS version

2. PostgreSQL (v12 or higher)
   - Download from: https://www.postgresql.org/download/
   - Verify installation: psql --version
   - Make sure PostgreSQL service is running
   - Remember your postgres superuser password during installation

3. npm (comes with Node.js)
   - Verify installation: npm --version

4. Git (for cloning the repository)
   - Download from: https://git-scm.com/downloads
   - Verify installation: git --version

5. For Mobile App:
   - Expo CLI (will be installed automatically via npx)
   - Expo Go app on your phone (for testing on physical device)
     - iOS: Download from App Store
     - Android: Download from Google Play Store
   - OR Android Studio / Xcode for emulators

6. Code Editor (recommended):
   - Visual Studio Code: https://code.visualstudio.com/

================================================================================
                     STEP 1: CLONE THE REPOSITORY
================================================================================

1. Open a terminal/command prompt

2. Navigate to your desired directory:
   cd your/projects/folder

3. Clone the repository:
   git clone https://github.com/JamesCyrel/agritrade.git

4. Navigate into the project:
   cd agritrade

5. Switch to the NestJS migration branch:
   git checkout nest.js-migration

================================================================================
                         STEP 2: DATABASE SETUP
================================================================================

1. Start PostgreSQL service (if not running):
   - Windows: Open Services (Win+R, type services.msc), find PostgreSQL, Start
   - Mac: brew services start postgresql
   - Linux: sudo systemctl start postgresql

2. Create the database:
   
   Option A - Using Command Line:
   - Open terminal/command prompt
   - Connect to PostgreSQL:
     psql -U postgres
   - Enter your postgres password when prompted
   - Create the database:
     CREATE DATABASE agritrader;
   - Exit psql:
     \q

   Option B - Using pgAdmin:
   - Open pgAdmin
   - Right-click on "Databases"
   - Select "Create" > "Database"
   - Enter name: agritrader
   - Click "Save"

3. Initialize the database schema:
   - Navigate to backend directory:
     cd backend
   - Run the init.sql file:
     psql -U postgres -d agritrader -f init.sql
   - Enter your postgres password when prompted

   This creates the following tables:
   - users (user accounts with roles: CONSUMER, FARMER, ADMIN)
   - profiles (user profile information)
   - verification_documents (farmer verification docs)
   - products (rice products listing)
   - product_images (product image URLs)
   - product_sack_sizes (product pricing by sack size)
   - consumer_addresses (delivery addresses)
   - payment_methods (saved payment methods)

================================================================================
                         STEP 3: BACKEND SETUP
================================================================================

1. Navigate to backend directory (if not already there):
   cd agritrade/backend

2. Install backend dependencies:
   npm install

   This will install all required packages including:
   - NestJS framework and related packages
   - PostgreSQL driver (pg)
   - Authentication packages (passport, JWT)
   - bcrypt for password hashing

3. Create .env file in the backend directory:
   - Create a new file named ".env" in agritrade/backend/
   - Add the following content (update with your credentials):
   
     # Database (Dual Database Architecture)
     # Primary (Supabase) - All writes go here
     PRIMARY_DB_URL=postgresql://postgres.[PROJECT]:[PASSWORD]@aws-0-[REGION].pooler.supabase.com:6543/postgres
     
     # Replica (Local PostgreSQL) - Read cache
     REPLICA_DB_URL=postgresql://postgres:postgres@localhost:5432/postgres
     
     # Sync Configuration
     SYNC_ENABLED=true
     SYNC_INTERVAL_MS=60000
     
     # Legacy support (for backwards compatibility)
     SUPABASE_DB_URL=postgresql://postgres:postgres@localhost:5432/postgres
     
     # JWT Secret - Change this in production!
     JWT_SECRET=your-super-secret-jwt-key-change-in-production
     
     # Server Port
     PORT=3000
   
   DUAL DATABASE ARCHITECTURE:
   
   The backend supports Supabase as primary + local PostgreSQL as read cache:
   
   - PRIMARY_DB_URL: Your Supabase connection pooler URL (port 6543)
     Get this from: Supabase Dashboard > Settings > Database > Connection string
     Select "Transaction Pooler" and copy the URI
   
   - REPLICA_DB_URL: Your local PostgreSQL for faster reads
   
   - SYNC_ENABLED: Set to "true" to enable automatic sync
   
   - SYNC_INTERVAL_MS: How often to sync (default: 60000 = 1 minute)
   
   How it works:
   - All WRITE queries (INSERT, UPDATE, DELETE) go to Supabase
   - All READ queries (SELECT) go to local PostgreSQL
   - Data syncs from Supabase to local every 60 seconds
   
   Note: To use local database only (development), set both URLs to local:

4. Seed the database with test data:
   npm run seed
   
   This will create:
   - 1 Admin user
   - 3 Farmer users (with profiles and approved verification)
   - 2 Consumer users (with addresses)
   - 6 Sample products (with sack sizes and pricing)

   Test Account Credentials (password for all: password123):

   - Farmer:   maria.farmer@example.com
   - Farmer:   pedro.farmer@example.com
   - Consumer: consumer1@example.com
   - Consumer: consumer2@example.com

5. Start the backend server:
   
   For development (with auto-reload on file changes):
   npm run start:dev
   
   For production:
   npm run build
   npm run start:prod

6. Verify backend is running:
   - Open browser: http://localhost:3000
   - You should see the API response or welcome message
   - Keep this terminal window open - the server must stay running

================================================================================
                         STEP 4: MOBILE APP SETUP
================================================================================

1. Navigate to mobile directory (in a NEW terminal window):
   cd agritrade/mobile

2. Install mobile app dependencies:
   npm install

   This will install all required packages including:
   - Expo framework
   - React Navigation
   - AsyncStorage for local data
   - Various Expo modules

3. Configure API URL:
   The mobile app automatically detects the API URL based on platform.
   
   The configuration is in: agritrade/mobile/services/api.js
   
   Default behavior:
   - Android: Uses http://192.168.12.1:3000
   - iOS/Web: Uses http://localhost:3000

   For physical device testing:
   You need to update the API URL to your computer's local IP address.
   
   Option A - Using Environment Variable (Recommended):
   Create a file named ".env" in agritrade/mobile/ with:
   EXPO_PUBLIC_API_URL=http://YOUR_COMPUTER_IP:3000
   
   Option B - Edit api.js directly:
   Open agritrade/mobile/services/api.js and modify the defaultRoot variable.

   To find your computer's IP address:
   - Windows: Open Command Prompt, type: ipconfig
     Look for "IPv4 Address" under your active network adapter
     Example: 192.168.1.100
   - Mac: Open Terminal, type: ifconfig
     Look for "inet" under en0 or en1
   - Linux: Open Terminal, type: ip addr
     Look for "inet" under your network interface

   Important: Your phone and computer must be on the SAME network.

4. Start the mobile app:
   npx expo start
   
   Or use npm script:
   npm start
   
   This will:
   - Start the Expo development server
   - Show a QR code in the terminal
   - Display options for running the app

5. Run the app on your device:

   Option A - Physical Device (Recommended for testing):
   - Install "Expo Go" app on your phone
     - iOS: App Store
     - Android: Google Play Store
   - Make sure phone and computer are on the same network
   - Scan the QR code from the terminal:
     - iOS: Use the Camera app
     - Android: Use the Expo Go app's scanner
   - The app will download and run

   Option B - Android Emulator:
   - Install Android Studio
   - Set up an Android Virtual Device (AVD)
   - Start the emulator
   - Press 'a' in the Expo terminal

   Option C - iOS Simulator (Mac only):
   - Install Xcode from App Store
   - Press 'i' in the Expo terminal

   Option D - Web Browser:
   - Press 'w' in the Expo terminal
   - Note: Some features may not work in web mode

================================================================================
                     STEP 5: NETWORK CONFIGURATION
================================================================================

For the mobile app to communicate with the backend:

1. Same Machine (Emulator/Simulator):
   - localhost or 127.0.0.1 should work
   - Android emulator may need: 10.0.2.2

2. Physical Device on Same Network:
   - Use your computer's local IP address (e.g., 192.168.x.x)
   - Ensure both devices are on the same WiFi network
   - Check that your firewall allows connections on port 3000

3. Using Mobile Hotspot (Recommended for reliable connection):
   - Enable mobile hotspot on your laptop/computer
   - Connect your phone to the laptop's hotspot
   - Find the hotspot IP address:
     - Windows: Usually 192.168.137.1 or similar
     - Run ipconfig and look for the hotspot adapter
   - Use this IP in your API configuration

4. Firewall Configuration (Windows):
   - Open Windows Defender Firewall
   - Click "Advanced settings"
   - Inbound Rules > New Rule
   - Select "Port" > TCP > Specific port: 3000
   - Allow the connection
   - Apply to all profiles
   - Name it "AgriTrade Backend"

5. Firewall Configuration (Mac):
   - System Preferences > Security & Privacy > Firewall
   - Firewall Options
   - Allow incoming connections for Node.js

================================================================================
                         TROUBLESHOOTING
================================================================================

DATABASE ISSUES:

1. "Cannot connect to database" or "Connection refused"
   - Check PostgreSQL service is running:
     - Windows: Services > PostgreSQL (should show "Running")
     - Mac: brew services list | grep postgresql
     - Linux: systemctl status postgresql
   - Verify database credentials in backend/.env file
   - Make sure database "agritrader" exists
   - Test connection: psql -U postgres -d agritrader

2. "Database does not exist"
   - Create the database: CREATE DATABASE agritrader;
   - Or run: psql -U postgres -c "CREATE DATABASE agritrader;"

3. "Permission denied" or "Authentication failed"
   - Check your postgres password in .env file
   - Try resetting postgres password if forgotten
   - Verify DB_USER is correct (usually "postgres")

4. "Relation does not exist" errors
   - Run the init.sql script to create tables:
     psql -U postgres -d agritrader -f init.sql
   - Then run the seed: npm run seed

BACKEND ISSUES:

5. "Port 3000 already in use"
   - Find what's using the port:
     - Windows: netstat -ano | findstr :3000
     - Mac/Linux: lsof -i :3000
   - Kill the process or change PORT in backend/.env
   - Update mobile app API URL if you change the port

6. "Module not found" errors
   - Delete node_modules and reinstall:
     - Windows: rmdir /s /q node_modules && npm install
     - Mac/Linux: rm -rf node_modules && npm install
   - Also try deleting package-lock.json before reinstalling

7. "Cannot find module 'bcrypt'" or native module errors
   - Rebuild native modules:
     npm rebuild
   - If still failing, reinstall bcrypt:
     npm uninstall bcrypt && npm install bcrypt

8. TypeScript compilation errors
   - Run: npm run build
   - Check for syntax errors in the terminal output
   - Make sure all dependencies are installed

MOBILE APP ISSUES:

9. "Network request failed" or "Could not connect to server"
   - Verify backend server is running
   - Check API URL configuration in mobile/services/api.js
   - For physical device: Use computer's IP, not localhost
   - Ensure both devices are on the same network
   - Check firewall settings (may block port 3000)
   - Try using mobile hotspot (see Step 5)

10. App crashes on startup
    - Clear Expo cache: npx expo start --clear
    - Delete node_modules and reinstall
    - Check for JavaScript errors in terminal

11. "Unable to resolve module" errors
    - Clear Metro bundler cache:
      npx expo start --clear
    - Reinstall dependencies:
      rm -rf node_modules && npm install

12. QR code not scanning
    - Make sure Expo Go app is installed
    - Try pressing 's' to switch to Expo Go mode
    - Check that phone camera has permission
    - Try typing the URL manually in Expo Go

13. App loads but shows blank screen
    - Check terminal for JavaScript errors
    - Verify API URL is correct
    - Check backend server logs for errors

SEED SCRIPT ISSUES:

14. "Seed script fails" or "Duplicate key" errors
    - The seed script clears existing data before inserting
    - If errors persist, manually clear the database:
      psql -U postgres -d agritrader -c "DELETE FROM products; DELETE FROM profiles; DELETE FROM users;"
    - Then run: npm run seed

15. "SUPABASE_DB_URL not found"
    - Add SUPABASE_DB_URL to backend/.env:
      SUPABASE_DB_URL=postgresql://postgres:your_password@localhost:5432/agritrader

GENERAL TIPS:

16. Always check terminal output for specific error messages
17. Google the exact error message for solutions
18. Make sure all environment variables are set correctly
19. Restart both backend and mobile app after config changes
20. Use console.log statements to debug issues

================================================================================
                        DOCKER SETUP (OPTIONAL)
================================================================================

Docker provides an easy way to run the database and backend without local setup.

1. Install Docker:
   - Download from: https://www.docker.com/products/docker-desktop
   - Or on Linux: sudo pacman -S docker docker-compose (Arch)
                  sudo apt install docker.io docker-compose-v2 (Ubuntu)

2. Start Docker service:
   - Linux: sudo systemctl start docker
   - Windows/Mac: Docker Desktop should start automatically

3. Run with Docker Compose:
   cd agritrade
   docker compose up --build

   This starts:
   - PostgreSQL database on port 5433
   - Backend API on port 3001

4. Stop services:
   docker compose down

5. Reset database (removes all data):
   docker compose down -v

Note: Docker ports are offset (5433/3001 instead of 5432/3000) to avoid
conflicts with local development servers.

1. Backend:
   - Create new module: nest generate module feature-name
   - Create controller: nest generate controller feature-name
   - Create service: nest generate service feature-name
   - Add routes in the controller
   - Update database schema if needed (init.sql)

2. Mobile:
   - Add new screen in app/ directory (file-based routing)
   - Add API calls in services/api.js
   - Import and use in your components
